System View Concepts
Terraforming Contractor #1380 · System view · 2026-10-21

让星系视图自然流动起来

现在的 System overview 是一个盖在游戏上的弹窗。下面有三种完全不同的做法，都能直接操作。每个画面里的四个世界就是你截图里的那四个：Home site、KX-506（你在这里）、KX-687、KX-868。

现在的问题（从代码和截图看到的）

像换了一个程序用 <dialog>.showModal() 盖住整个游戏，还要点 Close 回来。玩家的“在宇宙里”感觉被打断。SystemOverview.tsx
同一件事讲两遍左边是 3D 画面，右边又是一列卡片，把同样的信息写成小字。眼睛要在两边来回，卡片的方框感也最重。
说明离星球太远悬停后的描述在画面最底下一行，而星球在中间。看的是这里，读的是那里。
出发要点两次先点 Travel →，再弹出第二个确认对话框（travel-dialog）。出发应该是一个动作，不是两个窗口。
读不出星球的状态已去过的和只收到信号的靠“实体 / 线框”区分。残留岩石百分比、植物、居民都只写成文字，星球本身看不出来。
关系没画出来代码里知道谁的信号招来了谁（planetPosition 按 signal 链排布），画面上却没有任何连线。
Concept A

拉远

不换界面，只是把镜头拉远。你一直待在同一片宇宙里。

怎么用

  • 进入：点一下画面让它获得焦点，再滚轮往外滚（或拖下面的滑块）。游戏里的 “System overview ↗” 按钮变成同一个动作。
  • 阅读：星球变小时，大气点和模型细节淡出；别的世界从纸色里浮现；虚线弧把“谁招来了谁”连起来。名字贴在各自星球上方，悬停才展开一句话。
  • 出发：点一个世界，镜头滑向它，下面出现按住环。按住约 0.9 秒，镜头冲进去、纸色淡出，落在新星球的轨道上。

在 repo 里要改什么

  • 删掉 SystemOverview 的 dialog 和第二个 Canvas。
  • 复用其中的 mergeChunks（SYS-02：始终用世界当前被编辑过的网格）。
  • OrbitCamera 的范围放宽到约 30，加一个 system 层。
  • 把 DistantPlanetsView 的固定屏幕位置，换成真实方位（planetPosition）。
  • 工作量：中到高。

要注意

  • 同一个 Canvas 里要同时放几颗完整的星球网格，性能要测。
  • 当前星球照常运行，其他星球按 D-040 保持冻结，这个不变。
  • 缩放过程中左右两侧的面板要一起滑出，否则又变回“界面盖着画面”。
Concept B

信号星图

把它画成一张测绘图：每个世界是一块标本板，信号是连线。

Hover a plate · click to follow the signal there

怎么用

  • 进入：从游戏里滑出一张纸色的图，不是黑色弹窗。游戏仍在背后（轻度虚化），当前星球的机器人照常转。
  • 阅读：星球大小按真实半径画，所以大小可以直接比。外圈的弧表示剩下的岩石比例，虚线是它们之间的信号。每隔几秒从 Home 发出一圈涟漪，沿弧线传出去，就是你的广播。
  • 出发：点一块板，琥珀色的小标沿信号线滑过去（经过中转站就会停一下），到站时荡开一圈涟漪。

在 repo 里要改什么

  • 同样去掉 dialog，保留半透明的纸色覆盖层。
  • 用一个正交相机渲染各世界的网格，叠一层 SVG。
  • 连线数据已有：seed 路径里 /signal-N 就是父子关系。
  • 工作量：低到中，是三种里最容易做的。

要注意

  • 它是“看地图”，不是“在宇宙里”。沉浸感比 A、C 弱。
  • 固定排版不再是真实 3D 位置，spec 里 SYS-01 “navigable 3D spatial arrangement”要改写。
  • 每个去过的星球最多还能招来 5 个新星球（tuning.signal.maxPlanets），世界会越来越多，所以要有自动排版规则，避免互相压住。
Concept C

漂流

沿一条水平的带慢慢漂，一次只面对一颗星球，其余在两侧探出头。

Drag sideways · arrow keys

怎么用

  • 进入：画面向一侧漂开，当前星球居中，别的世界在两边露出一半。像翻一排标本。
  • 阅读：居中的那颗放大，状态直接画在它身上：幽灵外壳（被挖走的岩石）、绿点（植物）、竖线（天线）、暖色光点（居民）。下面只留名字和一句话。远近不同的世界有视差。
  • 出发：居中后按住下面的环，星球涨满画面，换成新的轨道视角。

在 repo 里要改什么

  • 新写一个一维相机（沿 x 漂移、居中吸附），其余复用网格。
  • system.ts 里的 describe() 数据已够用，只是换成画在星球上。
  • 工作量：中。

要注意

  • 并排比较两颗星球不方便，只能来回切。
  • 世界多了，这条带会很长，要有快速跳转。
  • 和 B 一样，SYS-01 的 3D 空间排布要改成一维顺序。

三个方案都能共用的两件事

1 · 把状态画在星球上，不写成小字

现在每个世界都靠一长串文字说明。下面这些记号，数据都已经在 describe() 里，只是换了表现方式。文字只在悬停或聚焦时补一句。

  • 幽灵外壳原来的球形轮廓。剩下多少岩石，一眼就能看出被挖走了多少。
  • 绿点植物，按真实位置分布。
  • 竖线加琥珀尖天线。有几根，就是还能发几次信号。
  • 暖色光点居民，会随它们躲藏、移动而变化。
  • 闪烁的琥珀灯机器人正在工作。暂停的世界灯是灭的。
  • 线框只收到信号、还没去过。只有真实大小，没有地形。

2 · 出发是一个动作，不是两个窗口

现在是 Travel → 然后再弹确认框。改成“按住”：松手就取消，所以不再需要二次确认。原来确认框里的话（“这个星球会暂停，资金会带走”）直接写在聚焦的说明里。

试试按住它。0.9 秒是我的起点，太短会误触，太长会烦，需要你上手感受后定。

另外两种出发动作：沿信号线拖那枚小标（B 很适合）；或者继续往星球里滚轮放大，直到“落”进去。

我的建议：以 A 为骨架，借 B 的线、借 C 的读法

  1. 用 A 的拉远当入口和结构：没有弹窗，镜头直接拉出去，你的“自然、流动、沉浸”主要靠这一点。
  2. 用 B 的信号弧线：弧线本来就是游戏的核心故事（你发出信号，宇宙回应），值得画出来，还能在每次广播时亮一下。
  3. 用 C 的方式读星球：幽灵外壳、绿点、天线、居民光点，直接画在星球上，列表可以整个删掉。
  4. 用“按住出发”替掉现在的两步弹窗。

如果你更看重“一眼看懂全局”，B 是最便宜、也最容易先做出来试的版本。如果更看重“一颗一颗地看”，选 C。

想先请你定的几件事

  1. 三个方向里，你更想要哪一种感觉？或者就按上面的组合？
  2. 拉远的时候，当前星球上的机器人还要继续动吗？（我建议继续，只是变成小光点。）
  3. 按住出发的时间长度，和要不要保留“这个星球会暂停”的提示。
  4. 只收到信号的星球，要不要在聚焦时慢慢“固化”成一个简单的球，还是始终保持线框？
